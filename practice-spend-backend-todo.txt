Practice Spend — Backend TODO List (Detailed)
=============================================

Work through these steps in order. Do one small group at a time.
When you finish a section (or get stuck), stop and check in with me before continuing.


==================================================
PHASE 1 — Create the Spring Boot project
==================================================

Step 1.1
Open your browser and go to: https://start.spring.io

Step 1.2
On the left side, set these options:
- Project → Maven
- Language → Java
- Spring Boot → leave whatever version is selected by default (3.x is fine)
- Group → type: com.practice
- Artifact → type: spend
- Name → type: spend
- Packaging → Jar
- Java → choose 17 or 21 (pick the same version you use in class)

Step 1.3
On the right side, click “Add Dependencies”.

Step 1.4
Search for and add these three dependencies one by one:
- Spring Web
- Spring Data JPA
- MySQL Driver

Step 1.5
Click the Generate button at the bottom.
A zip file will download.

Step 1.6
Unzip the downloaded file somewhere easy to find (for example next to your practice-spend frontend folder).

Step 1.7
Open the unzipped “spend” folder in your IDE (IntelliJ, VS Code, Eclipse, etc.).

Step 1.8
Wait for the IDE / Maven to finish downloading dependencies.
This can take 1–2 minutes the first time. Look for a progress bar or “indexing” message.

Checkpoint for Phase 1
You should now see a normal Spring Boot project structure, including a file called SpendApplication (or similar) that has the main method.


==================================================
PHASE 2 — Set up MySQL
==================================================

Step 2.1
Open MySQL the way you normally do (MySQL Workbench, command line, or another tool).

Step 2.2
Create a new database named exactly:
practice_spend

Step 2.3
Confirm the database was created successfully (you should see it in the list of databases).

Step 2.4
In your Spring Boot project, open the file:
src/main/resources/application.properties

Step 2.5
Clear out whatever is currently in that file (or leave comments if you prefer).

Step 2.6
Add configuration that does the following:
- Points Spring to the practice_spend database on localhost, port 3306
- Uses your normal MySQL username
- Uses your normal MySQL password
- Tells Hibernate to automatically create/update tables
- Turns on SQL logging so you can see the statements Hibernate runs

Step 2.7
Save the file.

Checkpoint for Phase 2
Do not start the application yet. Just confirm the database exists and the properties file is saved.


==================================================
PHASE 3 — Create the Expense entity
==================================================

Step 3.1
In the same package as SpendApplication (or in a new “model” sub-package), create a new Java class named:
Expense

Step 3.2
At the top of the class, add the annotation that marks this class as a JPA entity.

Step 3.3
Add the annotation that maps this class to a database table named “expenses”.

Step 3.4
Add a field called id:
- Type: Long
- Mark it as the primary key
- Tell JPA to generate the value automatically (identity strategy)

Step 3.5
Add a field called description:
- Type: String
- Mark it so the database column cannot be null

Step 3.6
Add a field called amount:
- Type: BigDecimal (best for money)
- Mark it so the column cannot be null
- Give it appropriate precision and scale for currency (for example precision 10, scale 2)

Step 3.7
Add a field called category:
- Type: String
- Mark it so the column cannot be null

Step 3.8
Add a field called date:
- Type: LocalDate
- Mark it so the column cannot be null

Step 3.9
Add a public no-argument constructor.
(JPA requires this even if it stays empty.)

Step 3.10
Add a second constructor that accepts description, amount, category, and date and assigns them to the fields.

Step 3.11
Add getters and setters for every field (id, description, amount, category, date).

Checkpoint for Phase 3
The Expense class should compile with no red underlines. You do not need to run anything yet.


==================================================
PHASE 4 — Create the repository
==================================================

Step 4.1
Create a new interface named:
ExpenseRepository

Step 4.2
Make the interface extend JpaRepository.

Step 4.3
Tell JpaRepository two things:
- The entity type is Expense
- The ID type is Long

Step 4.4
Leave the body of the interface empty.
You do not need to write any methods.

Checkpoint for Phase 4
The interface should be very short and have no errors.


==================================================
PHASE 5 — Create the REST controller
==================================================

Step 5.1
Create a new class named:
ExpenseController

Step 5.2
Mark the class as a REST controller.

Step 5.3
Set the base URL path for all methods in this controller to:
/api/expenses

Step 5.4
Add configuration that allows the React development server (http://localhost:5173) to call this API (CORS).

Step 5.5
Add a private final field for ExpenseRepository.

Step 5.6
Create a constructor that takes ExpenseRepository and assigns it to the field.
(Spring will inject it automatically.)

Step 5.7
Write a method that handles GET requests to /api/expenses and returns every expense.

Step 5.8
Write a method that handles GET requests to /api/expenses/{id} and returns one expense.
If the id does not exist, return a 404 response.

Step 5.9
Write a method that handles POST requests to /api/expenses.
It should accept an Expense in the request body and save it.

Step 5.10
Write a method that handles PUT requests to /api/expenses/{id}.
It should update the existing expense with the data from the request body.
If the id does not exist, return a 404 response.

Step 5.11
Write a method that handles DELETE requests to /api/expenses/{id}.
If the id does not exist, return a 404 response.
If it does exist, delete it and return a success response with no body.

Checkpoint for Phase 5
The controller should compile. You still have not started the application.


==================================================
PHASE 6 — Start the backend and test it
==================================================

Step 6.1
Run the main application class (the one with @SpringBootApplication).

Step 6.2
Watch the console output carefully.

What success looks like:
- Hibernate prints SQL that creates the expenses table
- You eventually see a message that the application started
- There are no long red stack traces

Step 6.3
If the application fails to start because it cannot connect to MySQL, check these three things:
- Is MySQL actually running?
- Is the database name exactly practice_spend?
- Are the username and password in application.properties correct?

Step 6.4
Once the application is running, open a browser or an API tool (Postman, Thunder Client, etc.).

Step 6.5
Send a GET request to:
http://localhost:8080/api/expenses
You should receive an empty list: []

Step 6.6
Send a POST request to the same URL.
In the request body, send JSON that contains:
- description (text)
- amount (a number, for example 12.50)
- category (text)
- date (in YYYY-MM-DD format)

Step 6.7
Send another GET request to the same URL.
You should now see the expense you just created, including an id that the database assigned.

Step 6.8
Send a PUT request to:
http://localhost:8080/api/expenses/{id}
(Use the real id from the previous step.)
Change at least one field (for example the description) and confirm the change is saved.

Step 6.9
Send a DELETE request to:
http://localhost:8080/api/expenses/{id}
Then send a GET again. The expense should be gone.

Step 6.10
Optionally open MySQL and look at the expenses table to confirm the rows appear and disappear as you create and delete them.

Hard checkpoint
Do not move to Phase 7 until create, read, update, and delete all work through the API.


==================================================
PHASE 7 — Connect the React frontend (do this last)
==================================================

Only start this phase after the backend is solid.

Step 7.1
In the React App component, remove (or comment out) the hard-coded list of sample expenses.

Step 7.2
Change the expenses state so it starts as an empty array.

Step 7.3
When the page first loads, ask the backend for the list of expenses and put the result into state.

Step 7.4
When the user submits the form to add a new expense, send a POST request to the backend, then update the local list with the response.

Step 7.5
When the user submits the form while editing an existing expense, send a PUT request to the backend, then update that item in the local list.

Step 7.6
When the user clicks Delete, send a DELETE request to the backend, then remove that item from the local list.

Step 7.7
Make sure both applications are running at the same time:
- Backend on port 8080
- Frontend on port 5173

Step 7.8
Test the full cycle in the browser:
- Add an expense → it appears in the list
- Refresh the page → the expense is still there
- Edit the expense → the change is saved
- Delete the expense → it disappears and stays gone after a refresh


==================================================
Mental model (keep this in mind)
==================================================

- Expense class          → defines the shape of one row in the database
- ExpenseRepository      → gives you the database operations without writing SQL
- ExpenseController      → turns those operations into HTTP endpoints the outside world can call
- application.properties → tells Spring how to connect to MySQL
- React fetch calls      → replace the old mock data with real API requests


When you finish a phase or hit an error, stop and tell me exactly where you are.
We will do the next piece together.
